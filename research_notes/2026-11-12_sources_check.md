# Перевірка джерел з дослідження 12.11.2026 — живі запити

Дата перевірки: 12.11.2026, хмарна сесія бота, curl з браузерним User-Agent (CLAUDE.md, розділ 10).
Що перевіряли: кожне джерело з `research_notes/2026-11-12_sources_research.md` — тестовим запитом до сторінки, RSS або API без ключа.
Нічого не реєстрував і не підключав від імені Славіка.

Як читати:
- «працює» — сторінка/RSS/API віддали 200 і справжній вміст (не заглушку).
- «блокує (код)» — сайт не пускає бота.
- «потрібен ключ» — API відповідає, але без ключа даних не дає.
- «тільки вручну» — автоматично не вийде або не можна за правилами.
- Висновок: ПІДКЛЮЧАЮ / НА ВИПРОБУВАННІ / ВРУЧНУ / ВІДКИНУТИ + причина.
- ПІДКЛЮЧАЮ і НА ВИПРОБУВАННІ йдуть у реєстр зі статусом «на випробуванні»; ВРУЧНУ — «ручний перегляд».

## Окремі перевірки (те, на що ти витрачатимеш час)

### 1. Etsy API: чи справді getShop / findShops дають transaction_sold_count з простим API key

Що зробив: завантажив офіційну специфікацію Etsy Open API v3 (`etsy.com/openapi/generated/oas/3.0.0.json`, відкрилась, 200) і сторінки документації `developers.etsy.com` (усі 200).

Підтверджено:
- Поле є. Цитата зі схеми Shop: «transaction_sold_count — The total number of sales (transactions) for this shop.» Тобто продажі за весь час, без грошей.
- Простого ключа достатньо. У getShop і findShops немає окремої вимоги OAuth; діє загальна вимога всієї специфікації — лише `api_key`. Для порівняння: getShopReceipts (замовлення) вимагає OAuth `transactions_r`.
- Обидва методи мають позначку «General Release — This endpoint is ready for production use».
- Що ще дає схема Shop: кількість активних лістингів, «улюблені» магазину, кількість і середня оцінка відгуків «in the past year» (за останній рік), дата створення, країна, чи у відпустці, чи магазин у США.
- Пошук лістингів (findAllListingsActive): параметри keywords, ціна від/до, категорія (taxonomy_id), країна магазину, сортування; до 100 результатів за запит («maximum: 100»). Віддає назву, теги, матеріали, ціну, «улюблені», категорію, дату створення.

Уточнення, яких не було в дослідженні (саме тут можна знову «обпектися»):
- findShops шукає лише за назвою магазину (єдиний параметр пошуку — shop_name). Знайти «200–500 магазинів у ніші» через findShops не можна. Робочий шлях: шукати лістинги за ключовими словами → брати з них shop_id → для цих магазинів робити getShop.
- Перегляди (views) у пошуку лістингів НЕ віддаються. Поле views є лише в повній картці лістингу (getListing / getListingsByListingIds). Цитата: «The number of times the listing has been viewed. This value is tabulated once per day and only for active listings… If 0, the listing has either not been viewed, not yet tabulated… or there was an error».
- Ключ — це пара. Цитата: «Every request to a v3 endpoint must include an x-api-key header containing your keystring and shared secret separated by a colon». Живий запит без ключа відповідає: «Invalid API key: should be in the format 'keystring:shared_secret'» (403).
- Ключ працює не одразу. Цитата з Quick Start: «Your API key is not active until it has been approved».
- Тип застосунку — найважливіше. У документації тепер два шляхи:
  - Seller App — «approved within minutes», але «scoped only to your registered shop» і «for your own shop use only». Для моніторингу чужих магазинів, найімовірніше, не підходить (дослівно не сказано, чи публічні дані чужих магазинів теж обрізаються, — не можу гарантувати).
  - Personal App — для «uses beyond their own shop», але «Personal Apps go through a deeper review process than Seller Apps». Скільки триває перевірка — не написано.
- Ліміти: у документації приклад — 150 запитів за секунду і 100 000 за добу, але це «example value»; реальні ліміти видно лише в кабінеті розробника після схвалення.
- Умови користування Etsy API (`etsy.com/legal/api`) для бота закриті (403). Через пошук текст розділу про кешування й аналітику знайти не вдалося. Документація каже: застосунки мають дотримуватися правил кешування з розділу 1 умов і показувати фразу «The term 'Etsy' is a trademark of Etsy, Inc. This application uses the Etsy API but is not endorsed or certified by Etsy, Inc.» Перед реєстрацією варто прочитати умови очима.
- Висновок: твердження «getShop/findShops дають transaction_sold_count з простим ключем» — правда за специфікацією. Але «перегляди лістингів» — лише через окремий запит по кожному лістингу, «findShops для ніші» — не працює, і потрібен саме Personal App з ручною перевіркою Etsy.

### 2. Gemini API: чи приймає посилання на публічне YouTube-відео

Що зробив: відкрив офіційну документацію `ai.google.dev/gemini-api/docs/video-understanding` (200) і сторінку лімітів.

Підтверджено, цитати:
- «You can pass YouTube URLs directly to Gemini API as part of your request».
- «Preview: The YouTube URL feature is in preview and is available at no charge. Pricing and rate limits are likely to change.»
- «For the free tier, you can't upload more than 8 hours of YouTube video per day.»
- «For the paid tier, there is no limit based on video length.»
- «For Gemini 2.5 and later models, you can upload a maximum of 10 videos per request.»
- «You can only upload public videos (not private or unlisted videos).»
- Уточнення до дослідження: «до 10 відео за запит» — це правило самого API для моделей 2.5+, а не лише Google AI Studio.
- Ліміти запитів free tier (скільки запитів на хвилину/день) залежать від моделі й рахуються на проєкт, а не на ключ; добовий ліміт обнуляється опівночі за тихоокеанським часом.
- Живий запит до API без ключа: 403 «Method doesn't allow unregistered callers» — очікувано, потрібен ключ.
- Висновок: працює за документацією; живим запитом із ключем не перевіряв (ключа немає).

## Побічні знахідки під час перевірки (не новини випуску, лише сигнал)

- Уточнення де minimis. Документ 91 FR 37801 від 24.06.2026 стосується лише відправлень через міжнародну пошту: «indefinite suspension of the de minimis administrative exemption for imports valued at $800 or less arriving through the international postal network». Набрав чинності 24.07.2026 (одна поправка — 24.06). У дослідженні написано «для всіх видів доставки» — це за цим документом не так.
- 91 FR 66638 від 22.10.2026: строк перенесено на 20.01.2027 лише для обов'язкового формального оформлення окремих поштових відправлень (ті, що під вимогами інших держорганів, мита за главами 98/99 або пільги за угодами).
- Нове у Federal Register, чого немає в дослідженні: 08.10.2026 — проєкт правила «Low-Value Shipments» (нові вимоги до informal entries до $2 500 і електронний тип для пошти), коментарі до 07.12.2026; 06.11.2026 — «Heightened Requirements for Foreign Importers of Record», чинне з 05.01.2027. ## Що в дослідженні не підтвердилося або виявилось неточним

1. De minimis: правило 24.06.2026 — лише для пошти, не «для всіх видів доставки».
2. Etsy API: findShops не шукає магазини за нішею; перегляди лістингів — лише окремим запитом по лістингу; ключ = keystring:shared_secret і працює після схвалення; для чужих магазинів потрібен Personal App з глибшою перевіркою.
3. Etsy IR RSS: адреса з дослідження — 404; робоча — press-releases/rss.
4. Укрпошта e-export: для бота закрито (403), не «відкриті сторінки».
5. ONS: частки онлайну в тексті бюлетеня немає, лише в датасеті.
6. YouTube Data API: search.list тепер рахується окремою квотою 100 викликів на день.
7. Gemini: «10 відео за запит» — правило API для моделей 2.5+, не лише AI Studio.
8. RSS магазину Etsy — працює (дослідження сумнівалось через DataDome).
9. Eurostat API працює без ключа (у дослідженні — «не тестувався»).
10. e-Residency €165 з 2027 — на відкритих сторінках не знайдено.

## Що не вдалося закрити

- Обсяги ключових слів — чесно немає автоматичного доступу (Trends — 429, API — alpha, Keyword Planner — через акаунт).
- Умови Etsy API щодо кешування й аналітики — сторінка закрита, текст не знайдено.
- GitHub etsy/open-api — недоступний з цієї хмари.
- Австралія й НЗ — офіційної частки онлайну немає.
- Instagram, TikTok, Meta Ad Library, Google Ads Transparency — лише вручну.
- Блогери: авторитетність не перевірено (чекаю імена).
- Склади в США, держпрограми, вимоги Shopify до OÜ/LLC — не перевірено.
